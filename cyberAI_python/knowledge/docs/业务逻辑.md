（一）定义与本质
业务逻辑漏洞是指因业务流程设计不严谨、权限控制缺失、参数校验不足等设计层面问题，导致攻击者可绕过正常业务逻辑，实现未授权操作（如越权访问、密码重置、篡改交易金额）的安全漏洞，属于 “设计漏洞” 而非 “代码实现漏洞”。

三、四大类核心漏洞（含实操细节）
（一）绕过验证类漏洞
指攻击者通过技术手段绕过网站的身份验证机制，实现未授权登录、密码重置等操作，核心包括 4 种细分类型： 软件实用程序

1. 弱口令漏洞
定义：易被猜测或破解的账号密码（如简单数字、个人信息关联密码），攻击者可直接登录或通过简单枚举获取权限。
常见弱口令类型：
简单字符组合：123456、666666、abc123；
个人信息关联：身份证后 6 位、姓名首字母 + 生日（如wangwei1999）；
键盘顺序：1qaz2wsx、2580（手机键盘中间行）；
默认口令：系统 / 设备出厂默认密码（如admin@123）、企业统一初始密码（员工未修改）。
实操挖掘：
定位登录页面，尝试常见弱口令组合（admin/123456、test/123456）；
结合社会工程学（如已知用户名、生日），构造针对性密码（如用户名lisi，尝试lisi123、lisi1990）。
防御措施：
注册 / 修改 / 重置密码时强制弱口令判定：要求密码包含 “数字 + 字母 + 特殊字符”，长度≥8 位；
禁止复用历史密码，定期提醒用户修改密码；
登录时检测弱口令，引导用户修改。
2. 暴力破解漏洞
定义：攻击者通过自动化工具（如 BP 的 Intruder 模块）穷举账号密码，利用验证机制不完善获取权限。
漏洞成因（满足任一即可）：
无验证码或验证码仅前端验证；
验证码不过期（后端验证但可重复使用）；
无账号锁定机制（输错多次仍可继续尝试）；
错误提示过于详细（如 “用户名不存在”“密码错误”，可枚举有效用户名）；
短信验证码过短（＜6 位）、无发送间隔限制。
特殊形式：撞库攻击：
原理：利用 A 平台泄露的账号密码，批量尝试登录 B 平台（依赖用户在多平台使用相同账号密码）；
特点：绕过验证码、锁定机制等防护，成功率高于普通暴力破解。
实操步骤（BP 爆破示例）：
打开 BP，拦截登录请求，发送至 Intruder 模块；
标记账号、密码参数为 Payload 位置；
加载字典（用户名字典 + 密码字典），选择爆破模式（如 “集群炸弹模式”，账号与密码一一对应）；
执行爆破，通过响应包长度差异（登录成功与失败的响应长度不同）筛选有效账号密码。
防御措施：
添加图片验证码：验证失败后立即刷新，一次失效；
账号锁定：连续输错 5 次，锁定 30 分钟以上；
模糊错误提示：统一提示 “用户名或密码错误”，避免枚举有效用户名；
短信验证码：长度≥6 位，输错 5 次锁定手机号；
增加 Token 机制：每次登录生成随机 Token，一次有效，防止重放攻击。
3. 客户端验证绕过
定义：服务器将验证信息（如验证码、用户 数据）或验证结果（如success/fail）返回前端，由客户端自行校验，攻击者可通过抓包修改数据绕过。
两大细分场景：
场景 1：服务器返回敏感验证信息（如短信验证码、密码），攻击者直接获取；
示例：短信营业厅登录，抓包发现服务器返回用户密码明文，直接使用该密码登录；
场景 2：服务器返回验证状态码（如0=失败、1=成功），攻击者篡改状态码；
示例：58 同城短信登录，输入错误验证码后抓包，将响应包中的fail改为success，成功登录。
实操判断方法：
输入错误验证码 / 数据，提交后观察是否能抓到请求包；
能抓到包→后端验证（需进一步测试验证码是否过期）；
不能抓到包→前端验证（可直接绕过）。
防御措施：
核心验证逻辑移至服务端，前端仅负责数据展示；
不向前端返回敏感验证信息（如验证码、密码）；
验证结果由服务端控制跳转，不依赖前端状态码。
4. 任意密码重置漏洞
定义：利用密码重置功能设计缺陷，攻击者可重置任意账号的密码。
常见成因：
重置问题过少 / 过简单（如仅问 “手机号后 4 位”，易被猜测）；
重置链接可猜测（如链接包含用户 ID，遍历 ID 即可获取他人重置链接）；
关键参数可篡改（如重置时将自己的手机号改为他人手机号，接收验证码）；
无二次身份验证（重置密码时不验证原密码、不绑定预设手机号）。
实操示例（关键参数篡改）：
以自己的账号（A 账号）发起密码重置，通过身份验证（如回答安全问题）；
进入设置新密码页面，抓包提交请求，发现请求体包含手机号参数（如phone=138xxxx1234）；
将手机号改为目标账号（B 账号）的手机号（phone=139xxxx5678），提交请求；
若服务器未绑定身份与手机号，B 账号的密码将被重置为新密码。
防御措施：
重置验证全在服务端执行，不依赖前端参数；
重置链接采用高度随机字符串（如 Token），有效期≤24 小时；
验证码 / 重置链接仅发送至预设手机号 / 邮箱；
避免连续身份验证（一次性收集所有验证信息，再执行重置）。
（二）越权访问类漏洞
指攻击者突破网站的权限控制机制，访问或操作超出自身权限的资源，分为水平越权和垂直越权两类：

1. 水平越权
定义：同权限用户访问其他用户的独有资源（如学生 A 查看学生 B 的成绩）。
核心原理：权限控制仅依赖前端传递的身份标识（如用户 ID、订单号），未在后端校验该标识与当前登录用户的关联性。
常见实操场景：
场景 1：基于身份标识（用户 ID / 用户名）；
示例：登录用户lucy后，访问个人信息的 URL 为http://xxx.com/user?name=lucy，将name改为lily，即可查看lily的个人信息；
场景 2：基于订单号；
示例：电商平台订单号为连续数字（如14768），遍历订单号14769、14770，可查看其他用户的订单信息（含提货码、收货地址）；
场景 3：基于文件名 / 参数；
示例：文件访问 URL 为http://xxx.com/file?id=2&type=1，修改type=2、id=3，可查看他人的营业执照、注册资料。
2. 垂直越权
定义：低权限用户访问高权限用户的资源（如普通用户添加管理员账号）。
常见实操场景：
场景 1：基于 Cookie/Session；
示例：锐捷路由器游客账号登录后，抓包发现 Cookie 值为user=guest，将其改为user=admin，获得管理员权限（可修改路由器配置）；
场景 2：基于高权限操作链接；
示例：抓包获取管理员添加用户的请求包（http://xxx.com/admin/addUser），使用普通用户的 Cookie 替换管理员 Cookie，提交请求，成功添加新用户。
防御措施：
采用成熟权限管理框架（如 Spring Security、Apache Shiro）；
操作前校验身份标识与当前用户的关联性（如查询订单时，校验订单所属用户 ID 与登录用户 ID 一致）；
关键操作（如添加用户、修改配置）需二次验证；
高权限模块（如管理后台）避免直接暴露在互联网，需 IP 白名单限制。
（三）交易类漏洞
指攻击者利用交易流程设计缺陷，篡改关键参数或绕过流程校验，获取经济利益，核心发生在电商、支付、积分兑换等场景：

1. 核心成因
客户端传递的交易参数（金额、数量、订单状态）未在服务端严格校验，仅依赖前端 数据，导致攻击者可任意篡改。 计算机科学

2. 三大细分类型
类型 1：参数篡改

定义：篡改交易关键参数（金额、数量），实现低价购买、虚假充值等；
细分场景：
篡改金额：将手机单价3000改为0.01，支付 0.01 元购买手机；
零数逻辑：将域名注册费关联参数1改为0，实现 0 元注册；
负数逻辑：支付时将金额20改为-30，导致账户余额增加（服务端执行余额-(-30)=余额+30）。
实操示例（酒店团购金额篡改）：
酒店团购页面显示 “两晚总价 150 元”，点击支付，抓包获取请求体（price=85&total=150）；
将price改为0.05、total改为0.1，提交请求；
服务端未校验参数真实性，最终支付 0.1 元完成团购。
类型 2：重放攻击

定义：抓取正常交易 / 活动的请求包，重复发送，实现重复获利（如重复领取积分、流量）；
示例：新浪微博抽奖送流量活动，抓包获取领取流量的请求包，使用 BP 的 Repeater 模块反复发送，无限领取流量。
类型 3：流程漏洞

定义：利用交易流程（如下单、退货、优惠券使用）的逻辑缺陷获利；
示例：购买主商品（3 元）+ 免费赠品（原价 10 元），下单后申请退货，服务端未区分主商品与赠品，将 13 元全额退款（多退 10 元）。
3. 防御措施
核心原则：客户端数据不可信，所有交易参数需在服务端二次校验；
参数校验：金额、数量等关键参数需与服务端预设值比对（如商品单价从数据库查询，不依赖前端传递）；
防重放：为每笔交易生成唯一订单号，一次有效，避免重复提交；
流程闭环：明确交易各环节的校验规则（如退货时仅退主商品金额，赠品不退款）。
（四）其他类型漏洞
1. 短信炸弹
定义：利用短信验证码无发送间隔限制，反复发送验证码，骚扰用户或耗费网站短信资源；
成因：短信发送接口未限制发送频率（如无 60 秒间隔限制）、未校验发送者身份；
防御措施：设置短信发送间隔（≥60 秒），连续发送 5 次后锁定手机号。
四、漏洞挖掘思路（纯手工核心流程）
（一）核心流程
定位关键业务模块：优先关注核心功能（登录注册、密码重置、订单查询、支付交易、权限管理）；
跟踪业务流程：模拟正常用户操作，记录每个环节的请求参数、响应 数据；
尝试参数篡改：修改身份标识（用户 ID、订单号）、交易参数（金额、数量）、状态码（success/fail），观察响应变化；
验证权限边界：低权限用户尝试访问高权限链接，同权限用户尝试访问其他用户资源；
确认漏洞存在：若篡改后实现未授权操作（如越权查看、低价购买），则漏洞确认。
（二）针对性挖掘示例
暴力破解漏洞：登录页面输入错误密码 5 次，观察是否有锁定机制、验证码是否刷新；
越权漏洞：订单查询页面修改订单号，观察是否能查看其他用户订单；
交易篡改漏洞：支付页面抓包，修改金额参数，提交后查看支付结果。
